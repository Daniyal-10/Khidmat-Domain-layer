# Artifact Request Checklist — send to Affan before the session

**Why this matters.** Per Framework Rule F-1, a finding needs to separate "domain reality" from
"organisational practice" from "local practice." A verbal answer alone rarely supports that
split. A real form, screenshot, or email thread does. Send this list a few days ahead so Affan
can gather what's shareable — do not wait until the session to ask.

**Redaction note to include when sending:** ask Affan to redact/remove any beneficiary names,
phone numbers, ID numbers, or other personal data before sharing anything. We need the
*structure*, not the *content*, of these artifacts.

---

## Checklist (send as-is to Affan)

Please share whatever you can from the list below — redacted or blank versions are perfect,
we don't need real beneficiary data:

- [ ] A **blank or redacted intake/registration form** (paper or digital screenshot)
- [ ] A **blank or redacted needs-assessment form or survey template**
- [ ] **System screenshots** showing status fields, dropdowns, or how "unknown/not assessed" is
      represented (if your system has this)
- [ ] Any **SOP or written guidance** for registration, deduplication, or determining whether a
      new registrant is an existing beneficiary
- [ ] A **referral or handoff form** used when a case moves to another person, service, or
      organisation
- [ ] A **donor agreement excerpt or eligibility checklist** showing funding restrictions
      (geographic, sectoral, population, time-limited) — redact financial figures if needed
- [ ] A **case management system export or screen view** (redacted) showing how one case's
      history/timeline is displayed
- [ ] An **email thread or written example** where two rules conflicted (e.g., donor reporting
      vs. beneficiary privacy, or eligibility vs. urgent need) and how it was resolved
      — names/identifying details redacted
- [ ] An **example of two sources disagreeing** about the same fact, and how that was recorded
      or resolved (redacted)
- [ ] A **PDM (post-distribution monitoring) or MEAL report template**, or an example of how
      outcomes are tracked separately from case closure
- [ ] Anything **your organisation's consent form** covers — what's asked, and what withdrawal
      language (if any) is included

## Interviewer prep note (not for Affan)

For each artifact received, before the session, pre-note which Review IDs it's likely to touch
(cross-reference `05-GROUND-TRUTH-REVIEW-MATRIX.md`) so you can ask targeted follow-ups live
rather than discovering the connection afterward. Example: a redacted donor agreement maps to
GT-OQ8 (funding restrictions) and possibly GT-OQ17 (funder altitude) if it references
cross-programme terms.

If Affan cannot share a given artifact (confidentiality, doesn't exist, not his to share), that
absence is itself worth noting — record it in the session log rather than silently dropping the
line item.
